好，那我们来把这两套系统”焊“在一起。


——

OKR 和 GTD 的衔接：让方向自然流进执行

核心原则：OKR 是”漏斗口“，GTD 是”管道“

不要把它们当两套系统维护。正确的做法是：OKR 只负责产出”什么值得做“的判断，然后立刻降解进 GTD 的既有结构里，之后日常运转完全交给 GTD。

你只在两个时刻需要同时面对 OKR：

1. 设定/调整 OKR 的时候（季度初或方向变化时）

2. 回顾 OKR 进度的时候（周回顾或月回顾）

中间的所有日子，你只跟 GTD 打交道。


——

具体衔接流程

第一步：O（目标）→ GTD 的”领域“（Areas of Focus）

David Allen 的 GTD 里有一个层级结构，很多人跳过不用，但它是 OKR 和 GTD 之间最好的接口：

愿景（50年）  ← 不展开
  ↓
3-5年视角     ← 不展开
  ↓
1-2年领域     ← ✅ OKR 的 Objective 落在这里
  ↓
责任范围      ← 工作、健康、关系、财务等
  ↓
项目（Projects）
  ↓
下一步行动（Next Actions）


操作方式： 每个 Objective 对应一个”领域“或”责任范围“的侧重方向。你不需要单独建一个 OKR 清单天天看——它已经被编码进了你对这个领域的理解里。

举例：O 是”建立可持续的收入结构“

→ 它对应 GTD 里”财务“这个责任范围

→ 你在这个领域下的所有项目，都自动对齐这个方向

第二步：KR（关键结果）→ GTD 的”项目“（Projects）

每个 KR 降解为一个或多个 GTD 项目。

操作方式：

KR	→ 降解为 GTD 项目
月被动收入达到 X 元	项目：搭建数字产品变现渠道
完成 3 个客户案例	项目：交付 A 客户 / 项目：交付 B 客户
体重降到 XX	项目：调整饮食结构 / 项目：建立运动习惯

关键动作： 每个项目创建时，在备注里标注它服务的 KR。一句话就行，比如”→ KR1“。这样回顾时你能快速判断：这个项目还在不在正确的轨道上。

第三步：项目 → GTD 的”下一步行动“（Next Actions）

这一步是纯 GTD，不需要 OKR 参与。但有一个技巧：

在周回顾时，用 OKR 做一次过滤：

拿你当前的 Next Actions 清单，逐条问：

• 这条行动，跟当前 OKR 有关系吗？

• 如果有 → 保留，正常推进

• 如果明显无关 → 放进 Parking Lot（Someday/Maybe）

• 如果不确定 → 问自己”不做它会怎样“，答案如果是”没什么“，就停

这一步的意义是：防止日常琐事把你的注意力从核心方向上拉走。


——

第三步半：Parking Lot 作为”OKR 的缓冲区“

这是你之前那段思考最妙的地方，把它正式化：

所有”有价值但跟当前 OKR 无关“的事 → 统一进 Parking Lot

它解决了 OKR 最大的实操问题：你总会冒出新想法，然后陷入”要不要加进当前目标“的纠结。

有了 Parking Lot，规则很简单：

• 新想法冒出来 → 先记下来

• 跟当前 OKR 直接相关 → 降解为项目/行动

• 不直接相关但有价值 → 停进 Parking Lot

• 回顾 OKR 时顺便翻 Parking Lot → 看有没有该激活的

这样你的 OKR 不会被新想法污染，你的好想法也不会被 OKR 的聚焦性杀死。


——

第四步：回顾节奏的对齐

频率	做什么	涉及哪套系统
每天	看 Next Actions，执行	纯 GTD
每周	清空收件箱 + 项目复盘 + 用 OKR 过滤行动清单	GTD 为主，OKR 做过滤
每 2-4 周	翻 Parking Lot	纯 GTD
每月/季度	检查 KR 进度，决定是否调整 OKR	纯 OKR
季度初	设定新 OKR → 降解进 GTD 项目层	OKR 产出，GTD 承接


——

一个完整的例子走一遍

季度初设定 OKR：

O：建立可持续的个人变现系统

KR1：上线 1 个数字产品

KR2：积累 500 个精准订阅用户

降解进 GTD：

领域：事业/变现
├── 项目：数字产品研发
│   ├── [ ] 确定产品形态（下一步行动）
│   ├── [ ] 写第一版大纲
│   └── [ ] 制作 MVP
├── 项目：内容分发渠道建设
│   ├── [ ] 选定 2 个主平台
│   ├── [ ] 发布第一周内容日历
│   └── [ ] 设计引流钩子
└── 项目：订阅转化路径搭建
    ├── [ ] 写落地页文案
    └── [ ] 配置邮件自动回复


日常运转：

你每天只看 Next Actions 清单，根本不需要想 OKR。但因为你每个项目都标注了”→ KR1“或”→ KR2“，你的潜意识知道自己在为什么而做。

周回顾时：

• 项目进度正常 → 继续

• 某个项目停滞 → 是前置条件没满足？→ 检查 Parking Lot 或项目支持材料

• 发现一条行动跟 OKR 无关 → 移入 Parking Lot

• 发现 Parking Lot 里某条突然跟新 KR 有关了 → 激活，降解为项目


——

最容易踩的坑

坑 1：两套系统各自维护，变成双倍负担

解法：OKR 只在季度初和月回顾时”出场“，其余时间它隐身。GTD 是日常唯一界面。

坑 2：OKR 设得太满，所有事都想塞进去，Parking Lot 形同虚设

解法：OKR 最多 3 个 O、每个 O 最多 3 个 KR。塞不进去的，就是 Parking Lot 的料。

坑 3：回顾时只看 GTD 不看 OKR，慢慢偏离方向

解法：周回顾模板里固定加一项：”当前行动是否对齐本季 OKR？“——30 秒扫一眼就够。


——

你现在可以做的第一件事

打开你现有的工具，做这一个动作就够了：

把当前 OKR（哪怕是非正式的）列出来，然后逐条问自己：它目前在 GTD 的哪个项目里？

• 有对应项目 → 标注一下”→ KRx“

• 没有对应项目 → 要么新建，要么承认它还没到执行时机，放进 Parking Lot

• 发现 OKR 里有条根本降解不出任何行动 → 它可能是个愿望，不是个目标，考虑调整

做完这一步，两套系统就通了。
