# UI 和 UX 的分界

## 为什么要把一件事拆成两面

评价一个界面的时候，最容易发生的事是把两件不同的问题混在一起说。

「这个界面很乱」——说的是东西摆得乱，还是用起来绕？「这个流程很别扭」——是页面难看，还是步骤太多？说的人自己也未必分得清，于是改的时候常常改错地方：该删的标签没删，该合并的步骤没合。

分成两面之后，每句话都有地方放，改的人也知道该动哪里。

## 两面各自是什么

**UI 是界面这个物件。** 它显示什么、怎么显示、摆在哪、字多大、有没有报错的样子。一句话：把它截图下来，你还能判断的那些，都是 UI。

**UX 是走完一遍的过程。** 从打开到拿到结果，中间经过几步、有没有卡住、错了能不能回来、换台机器还行不行。一句话：必须亲手操作才能判断的，都是 UX。

截图判 UI，操作判 UX——这就是那条分界判据的由来。它不是学术定义，是为了让两个人评分时能落到同一边。

## 为什么要强调不重复扣分

同一个问题常常两面都能记一笔。

比如「报错只有一行字，没说怎么办」。它既是 UI 的问题（错误状态没显示全），也是 UX 的问题（出错之后没有恢复路径）。如果两面各扣一次，同一个毛病被罚两遍，分数就失真了——它反映的是条文写重了，不是产品差两倍。

所以规矩是：按主责面记一次。哪一面是这个问题的主要归属，就记在哪一面，另一面不再记。

## 几处常见的混淆

**「界面很丑」通常是 UI，但不计分。** 章程里不设美观维度，因为观感不影响任务完成就不该进分数。真正会进分数的是「因为排布，我不知道该点哪」——那是信息层级，属于 UI 里可判定的部分。

**「流程太长」是 UX。** 步数多本身不是错，错在每一步都要重新想「我现在在哪、接下来干嘛」。

**「看不懂术语」两边都沾。** 界面上写着编译开关的名字，是 UI 的文本问题；它导致人不敢往下点，是 UX 的发现障碍。按主责面记 UI（那行文本本来就不该出现），UX 不重复记。

## 怎么用它

拿到一个界面，先截图，把截图能回答的问题答完：四种状态齐不齐，一屏有没有一个明显的下一步，文字里有没有外行看不懂的词。

答完再动手走一遍：从头到尾记步数，试着回一次源头，故意走错一次看能不能回来。

两遍分开做。别在走的过程中顺手评判摆设，也别在截图的时候脑补流程会怎么走。
