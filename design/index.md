# 可用性评分总纲

## 它管哪一件事

一件事「能用」和「好用」是两回事。程序跑得通，不等于人用得顺。

可用性只管后一件事：一个人站在这东西面前，能不能自己走完一遍，拿到他要的结果，中间不用问人。

它不关心功能多不多、技术难不难，只关心人和它打交道的那几分钟。

## 人一般卡在三个地方

**不知道该点哪。** 界面上一堆东西，没有哪一个看起来像是「我该从这里开始」。人来回扫几遍，然后退出去——这种退出不留记录，你不会知道有人来过。

**做完了找不到出处。** 屏幕上给了结果，但没给结果从哪来。要核对就得换一个工具、翻另一个目录，一趟下来结果基本作废：没法确认的东西不能用。

**出错了不知道怎么办。** 报了一行字，说的是「哪里坏了」，不是「我现在该做什么」。人把这行字读三遍，然后重跑一遍，得到同一行字。

这三个卡点分属两面：不知道点哪是 [UI 的信息层级](ui.md)，找不到出处与出错不知怎么办是 [UX 的任务闭环与可发现](ux.md)。剩下三条判据——状态齐备、可访问与一致、容错与降级——补的是另外两类反复出现的分歧：界面该显示的没显示，环境变了人不知道。

## 为什么值得单独立规矩

因为卡住的代价全在暗处。

人不会告诉你他放弃了。他会自己猜：是不是我用错了、是不是我环境有问题。猜几次之后就不再来了，而你的数据里只少了一次访问，看不出别的。

更麻烦的是，卡住经常被当成用户的问题。「他没看说明」「他不仔细」——真出问题的地方往往在界面上，但界面不会自己举手。

所以判定要写成能执行的检查，不能是「用起来要顺」这种话。后者每个人理解都不一样，落实的时候就会变成各做各的。

## UI 和 UX 的分界

**UI 是界面这个物件。** 它显示什么、怎么显示、摆在哪、字多大，以及四种状态——空、加载、错误、成功——齐不齐。一句话：把它截图下来，你还能判断的那些，都是 UI。

**UX 是走完一遍的过程。** 从打开到拿到结果，中间经过几步、有没有卡住、错了能不能回来、换台机器还行不行。一句话：必须亲手操作才能判断的，都是 UX。

截图判 UI，操作判 UX——这就是分界判据的由来。它不是学术定义，是为了让两个人评分时能落到同一边。

分成两面还解决一个记账问题：同一个问题常常两面都能记一笔。比如「报错只有一行字，没说怎么办」，既是 UI 的问题（错误状态没显示全），也是 UX 的问题（出错之后没有恢复路径）。两面各扣一次，同一个毛病被罚两遍，分数反映的就是条文写重了，不是产品差两倍。所以规矩是按**主责面**记一次，另一面不再记。

## 分数怎么算

六条判据分两面，每条按 0–100 打分再乘权重：**UI 三条合计 40，UX 三条合计 60**，总和 100。

理由是：界面摆得不漂亮，人还能忍；走不完流程，人就不来了。真正让人流失的是走不完和走错，不是看不顺眼。这个比例按目前有限的实测定，样本多了会再调。

**两面分开报分。** 只报总分会藏住问题：UI 极好、UX 极差，加权后可能是个中等分，看起来「还行」；两个数摆在一起，差多少一眼可见，改的人知道该往哪边使劲。

**没测的不给分。** 整维没测的不参与加权，另外标注覆盖率；维内只测了一部分的，得分只反映已验部分，没测的列成「待验」。一旦允许按代码推断给分，分数就变成「我觉得它应该没问题」——评审的意义正在于把「我觉得」换成「我测过」。

## 三条硬门槛

六条判据都是程度问题：闭环断得厉害还是轻微，术语出现得多还是少。程度可以用分数表达。

有三类问题不是程度问题：报错不给动作、参数被静默改、环境错误装成没数据。三者的共同点是**输出没说真话**——要么没说话，要么说错了。人靠界面自己纠正不过来，卡在入口之后后面的一切都不存在，其他维度做得再好也救不回来。

判据里的失败不是这样：找不到出处，人会去别处找；走错一步，人能退回来。察觉不到、也绕不过去的，才配当门槛。

所以这三类不参与加权，单独拎出来：任一不过，总分封顶 60，且不叠加——封顶是结构性缺陷的标记，不是第二次罚款，六维里已经按表现扣过分了。挂了几条写在门槛结论里，不写在分数里。

**G1 报错要给可照做的动作。** 「指出环境有问题」不算动作，「DISPLAY 未设置，可以用 --dump 在没有显示环境的情况下照常输出」才算。给一个照做无效的命令，跟没给一样。

**G2 不得静默改变语义。** 参数被修正、回退、取近似值时必须说出来；语义上无效的值必须拒绝。默认值不算——用户没给，就不存在修正。

**G3 环境错误不得伪装成空结果。** 判定靠对照实验：注入一个环境错误，再取一份真空数据，两份输出只要有一处不同（标准输出或退出码）就算过，完全相同就判不过。怎么跑这个对照、怎么记结果，见[可用性实测手册](../../handbook/design/usability-testing.md)。

三条门槛在判据里各有一处落点：G1 是 [UX 可发现](ux.md)的第三句，G2 是 [UX 容错与降级](ux.md)的前两句，G3 是 [UI 状态齐备](ui.md)里「空和错误要能分开」。不是两套规矩——同一个毛病，分数上按表现扣，结构上不过就封顶，封顶不再另扣。

## 第一次怎么走

1. **走一遍，留证据。** 不看文档走完全程，记下犹豫的时刻，同时留每屏截图（空、加载、错误、成功尽量截全）、从打开到拿到结果的步数、出错时那行字的原文。只记感受不记证据，打分那一步就没有可对照的东西。
2. **截图先判，操作后判。** 两遍分开做：别在走的过程中顺手评判摆设，也别在截图的时候脑补流程会怎么走。同一个问题按主责面只记一次。
3. **对着六条打分。** [UI 三条](ui.md)与 [UX 三条](ux.md)一条一条过，记「我在哪犹豫了」，不是「它违反了第几条」——条文是后来对账用的，卡住的感觉才是判断的起点。
4. **先跑三条门槛，再合分。** 任一不过记封顶 60；分面报分；把没测的地方列出来。

走的时候别看文档。文档是给已经会用的人查的，新人第一次接触时没有文档可看——而新人恰恰是最容易流失的那批人。

走完问三个问题：我找到入口了吗，我拿到结果了吗，我出错的时候知道下一步吗。三个里有一个答不上来，就值得回头改。

没测的清单和分数一样重要——它告诉你下一次该测什么。条文正本在[人类可用性评分章程](../../bylaw/design/usability.md)。
