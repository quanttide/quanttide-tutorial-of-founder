反事实推演：用数学模型验证历史决策
反事实推演的核心不是"跑一遍引擎"，而是"守住不变量 + 校准蓝方AI + 用史实验证 + 保留模糊度"这套纪律——守住纪律，推演就是验证；守不住，就是编故事。学术界对反事实历史（counterfactual history）有专门的方法论讨论，军事史领域尤其成熟；兰彻斯特方程、蒙特卡洛模拟等技术工具也有成熟的军事应用范式。本文给出从分叉时刻选定到内容化呈现的完整落地方案，以豫东战役1948年6月15日"改打开封"决策为例。
一、两种反事实，只做"决策反事实"
学术界把历史反事实分为两类，这对内容定位至关重要。
类型一：决策反事实——在同一态势下，换个决策会怎样。
类型二：状态反事实——改变某个客观变量（天气、兵力、时间）会怎样。
该做的是类型一，原因有三：
• 它直接对应"验证决策"这个卖点——观众想看的是"粟裕换成打五军会怎样"，不是"如果1948年雨季提前一周会怎样"。
• 它的数据需求更少，只需要"同一初始态势 + 不同决策方案"，不用重构整个战场环境。
• 它天然带叙事性，符合视频内容结构。
类型二可以留到番外（比如"如果黄百韬晚到12小时"），主线内容别碰。
二、反事实推演的完整工作流（六步法）
第一步：锁定"分叉时刻"（Fork Point）
这是整个推演的地基。分叉时刻必须满足三个条件。
条件	豫东案例（6月15日决策）	验证方式
历史上确实有过另一个选项	粟裕原定"歼灭第五军于鲁西南"的方案真实存在	电报原文、会议记录
决策前后态势有明确数据记录	6月15日的兵力部署、位置、机动速度	电报、战后总结
分叉后的结果对观众有冲击力	坚持打五军＝可能被三面合围	事后各兵团位置可推算
分叉时刻选错的典型症状：分叉太早（如"如果粟裕同意渡江"），变量爆炸，推演失去可信度；分叉太晚（如"帝丘店决战时如果多两个纵队"），结果几乎注定，没有戏剧性。
第二步：建立"不变量清单"（Invariant List）
这是反事实推演最容易被忽视、也最影响可信度的一步。反事实推演只能改变"决策"，不能改变"决策时刻的客观条件"。需要把6月15日态势下所有不变的要素列成清单：
不变量清单（6月15日豫东）：
□ 双方部队位置（各纵队坐标）
□ 双方兵力、装备、战斗力系数
□ 邱清泉、胡琏、区寿年、黄百韬各兵团的位置与机动速度
□ 黄泛区地形、道路状况
□ 天气、昼长（影响空袭与机动）
□ 后勤补给状态
□ 双方指挥官的反应速度参数（这是最敏感的）
任何一条"不变量"被偷偷改变了（比如为了推演结果好看把邱清泉的行军速度调慢了），推演就从"验证"变成了"编故事"——这是军事区观众最反感的行为。
第三步：定义"决策差异"（Decision Delta）
反事实方案和历史方案必须用同一张"决策描述表"来定义，避免叙述性偏差。
```python
# 决策描述表：6月15日分叉点
historical_plan = {
    "name": "改打开封（史实）",
    "phase_1": {"action": "siege_kaifeng", "units": ["3Z", "8Z"], "target": "开封守军"},
    "phase_2": {"action": "block_aid", "units": ["1Z","4Z","6Z","11Z(中野)"], "line": "睢杞线"},
    "phase_3": {"action": "field_battle", "target": "区寿年兵团"}
}
counterfactual_plan = {
    "name": "坚持打五军（反事实）",
    "phase_1": {"action": "envelop", "units": ["1Z","4Z","6Z","8Z"], "target": "邱清泉第五军"},
    "phase_2": {"action": "block_aid", "units": ["3Z","10Z"], "line": "鲁西南北线"},
    "phase_3": {"action": "pursue", "condition": "五军被歼后转入追击"}
}
```
关键：反事实方案必须"在决策者当时的信息条件下"是合理的——粟裕坚持打五军是完全理性的选择（本来就是原方案），这个反事实才成立。如果做"粟裕用火星科技"那种反事实，就没有讨论价值。
第四步：给引擎设定"蓝方AI"（技术核心）
反事实推演最难的环节是：历史上国军怎么应对，在反事实分支里国军也会怎么应对吗？这里有三档做法，难度递增。
档位	做法	可信度	工作量
低	蓝方完全按史实行动，不响应红方反事实方案	低	半天
中	蓝方用简单反应规则（如"被围则收缩待援 + 邻近兵团驰援"）	中	一周
高	蓝方用AI（MCTS/RHEA）自主决策	高	一个月+
建议从中档起步。具体规则可以这样写：
```python
# 蓝方简单反应AI规则集（示意）
if unit.is_engaged:  # 交战时
    unit.speed *= 0.3  # 机动下降
    if unit.besieged and unit.supply < 0.3:  # 被围且补给断
        unit.request_reinforcement(nearest_kmt_unit, radius=100)  # 呼叫100km内援军
if unit is reinforcement:
    # 邱清泉式反应：优先救援但受地形限制
    if terrain.is_huangfanqu:  # 黄泛区
        unit.speed *= 0.6
    unit.move_to(besieged_unit.position)
```
蓝方AI的行为必须用史实验证：拿"史实的红方方案"让蓝方AI跑一遍，看它的反应是否贴近历史上国军的实际动作。如果AI反应和史实不符，说明反应规则有问题，先校准再用于反事实。这个"用史实校准AI"的过程本身就是视频内容——观众看到为了严谨做了这么多步，人设立刻立住。
第五步：跑推演 + 输出"结果差异表"
反事实推演不是只跑一遍，要跑三组：
• 史实组：红方史实方案 + 蓝方史实行为 → 用于校准（结果应接近真实史实）
• 反事实组：红方反事实方案 + 蓝方AI反应 → 主推演
• 敏感性组：反事实方案 + 蓝方AI反应的参数扰动（比如蓝方反应速度±20%） → 看结果是否稳定
敏感性组是学术推演的标配，但对视频来说是隐藏加分项——可以在视频里只用一句话带过（"我们还测试了参数变化±20%的情况，结论不变"），但这句话的杀伤力巨大。
指标	史实组（校准）	反事实组	差异
开封是否攻克	是	否（未攻城）	-
歼敌数	9.3万（史实）	待推演	?
自损数	3.3万（史实）	待推演	?
邱清泉兵团状态	未受重创	待推演	?
中原战局影响	打破僵局	待推演	?
第六步：把推演结果转成叙事（内容化）
推演跑完不是结束，还要转成视频叙事。推演结论绝对不能简单说"X比Y好"，要用三层结构呈现：
• 第一层：数据呈现——把三组推演的对比表格放出来，用"引擎推演显示"作为限定语，不下价值判断。
• 第二层：机理解释——解释为什么会这样（比如"反事实方案下红方被三面合围，是因为鲁西南狭小地带无法展开兵力优势，这正是平方律的数学体现"）。
• 第三层：历史印证——引回到粟裕自己的判断："粟裕在回忆录里说'不能稳操胜券'，和引擎推演的结论一致……"——用引擎印证历史人物，而不是用历史人物印证引擎，这个方向别搞反了。
三、技术栈落地：qtgame-war 与 Jomini 的分工
qtgame-war（主引擎）：
• 机动模型：六角格地图、行军速度、地形修正
• 交战触发：判断两个部队是否接触
• 交战解算：调用 Jomini 的兰彻斯特方程
• 蓝方AI：反应规则（第三步的简单规则集）
• 时间轴推进：6小时/回合，推演30–40回合（豫东全程）
Jomini（数学底座）：
• 平方律解算（现代火器战争）
• 需要手工标定参数：华野战斗系数 vs 国军战斗系数
• 参数标定方法：用史实数据反推（如"开封攻坚，3万守军48小时被歼"→ 解出攻方系数）
输出层：
• 每回合导出JSON：`{turn, unit_id, position, strength, morale, engaged_with}`，交给 Blender/Godot 渲染。
Jomini参数标定的具体做法（实际操作中最麻烦的一步）：
```python
# 用史实数据反推战斗系数
# 史实：开封守军3万人（整68师等），华野3Z+8Z约8万人，48小时破城
# 设攻方系数 alpha，守方系数 beta（守军依托城防，beta有加成）
# 用兰彻斯特平方律，在 T=48h 时守军战损率应约 90%
# 试不同的 alpha/beta 组合，找到符合史实的解
from scipy.optimize import minimize
def loss_rate_diff(alpha, beta, A0=80000, B0=30000, T=48):
    # 平方律解析解
    import math
    r = math.sqrt(alpha*beta)
    c = math.sqrt(beta/alpha)
    B = B0*math.cosh(r*T) - (1/c)*A0*math.sinh(r*T)
    actual_loss_rate = 0.9
    predicted = max(B, 0)/B0
    return abs(predicted - (1-actual_loss_rate))
# 用优化器找最优参数
```
这个标定方法本身也可以做成一期番外（"我是怎么给引擎调参数的"），军事区观众对这种"幕后过程"内容接受度极高。
四、反事实推演最容易翻车的五个地方
翻车点1：拿结果倒推过程
跑出来的推演结果如果和历史不符，绝不可以说"这说明历史记载有误"——引擎是粗糙模型，历史是真实发生的事，冲突时先怀疑参数，别怀疑史实。这是学术反事实推演的铁律。
翻车点2：偷偷改参数让结果好看
做"粟裕打五军"的反事实，如果邱清泉AI表现得太傻导致红方大胜，观众一眼就能看出来。敏感性测试的目的就是检验结果是不是依赖某个特定参数——如果结果对参数极其敏感，就老实说"这个推演在参数A下得到结果X，在参数B下得到结果Y，说明这个决策的关键是XXX"。
翻车点3：过度戏剧化反事实结果
"如果粟裕坚持打五军，华野会被全歼"这种结论过于绝对，会招致军事区高手的驳斥。正确的表达是"引擎显示反事实方案下红方可能承受更大损失"——保留模糊度，展示推演过程，不下死结论。
翻车点4：忽略信息不对称
粟裕6月15日决策时并不知道黄百韬会从东边杀过来。做反事实推演时，反事实方案里的红方也不能拥有"上帝视角"——如果你的AI在反事实分支里提前调兵防黄百韬，那就是作弊。
翻车点5：把推演当"答案"，其实它只是"参照"
学术界的反事实推演被批评最多的就是这一点。在视频里要主动说清楚："引擎推演不是对历史的审判，而是帮助我们理解当时决策者面临的约束"——这句话加上去，就从"民科沙盘UP主"直接升级为"严肃军事内容创作者"。
五、一期完整内容结构示范
以首期"6月15日改打开封"为例，用六步法填充内容：
```
0:00-0:30   钩子：粟裕军令状+两次电报
0:30-2:00   分叉时刻：6月15日态势图，交代原方案vs新方案
2:00-4:00   方法论展示（1分钟）：
            - 不变量清单快闪
            - 蓝方AI的史实校准过程
            - （这段是差异化核心，一定要放）
4:00-8:00   史实组推演：跑历史方案，展示过程与结果
8:00-12:00  反事实组推演：跑"坚持打五军"方案
            - 重点展示蓝方AI如何反应（邱清泉/胡琏合围）
12:00-14:00 结果对比表+机理解释（平方律+地形约束）
14:00-15:00 历史印证：粟裕回忆录+中央"独立处置"电报
            收尾钩子：开封3天破城的攻城推演
```
总长控制在15–20分钟，方法论展示部分压缩到1–2分钟，但一定要放——这是灵魂。
收尾：先校准，再反事实
先把"史实组校准"这一步做扎实，让引擎在史实条件下能跑出接近真实史实的结果，再开始反事实分支——校准不过关就做反事实，等于在流沙上盖房子。
