反事实推演：用数学模型验证历史决策
反事实推演就是把同一场仗重放两遍：第一遍照历史的命令打，验证程序能跑出接近史实的结果；第二遍只换一条命令，看结果差在哪。守住不变量、校准蓝方AI、保留模糊度，推演才是验证而不是编故事。本文以豫东战役1948年6月15日"改打开封"决策为例，从最简单的"重放两遍"讲起，一直讲到结果怎么变成视频内容。
一、核心玩法：把同一场仗重放两遍
整套方法只讲一件事：把1948年6月15日重放两遍——一遍按粟裕真实的命令打，一遍换成他本来想打的方案，比较两次结果差在哪。
第一遍：照历史打（验证程序靠谱）
程序里输入6月15日的兵力位置：华野各纵队在哪、国军邱清泉、区寿年、黄百韬各兵团在哪。红方执行"打开封"。程序一回合一回合计算（每回合6小时），跑完应该跟历史差不多：开封攻克、歼敌约9万。如果跑出来跟历史差很远，说明程序参数没调对，先修参数，不往下走。
第二遍：换命令打（正片）
兵力位置、国军、地形，全部跟第一遍一模一样，只改一条命令：不打开封，改为打邱清泉的第五军。程序再跑一遍。这一次邱清泉被攻，附近的国军会来救——两遍结果一比，就知道"改打开封"这个决策到底高明在哪。
两遍之间的唯一差别叫"决策差异"：除命令外什么都不变。这个"什么都不变"的展开，就是后面所有纪律的来源。
为什么顺序不能反？程序就是一台秤，历史就是已知的体重——你空手站上秤显示150斤、可实际130斤，之后称出的"穿羽绒服重几斤"就没人信了。第一遍等于让程序做一份已经批过卷的题：对上答案（开封迅速破城、歼敌9万上下），这台秤才准；对不上，回去修参数。顺序反了，第二遍的数字全是错公式算出来的，看着热闹全是假的。先对答案，再做实验。
二、先选对分叉：什么样的时刻值得重放
不是每个战役节点都能这么玩。分叉时刻必须同时满足三个条件。
条件	豫东案例（6月15日决策）	验证方式
历史上确实有过另一个选项	粟裕原定"歼灭第五军于鲁西南"的方案真实存在	电报原文、会议记录
决策前后态势有明确数据记录	6月15日的兵力部署、位置、机动速度	电报、战后总结
分叉后的结果对观众有冲击力	坚持打五军＝可能被三面合围	事后各兵团位置可推算
分叉时刻选错的典型症状：分叉太早（如"如果粟裕同意渡江"），变量爆炸，推演失去可信度；分叉太晚（如"帝丘店决战时如果多两个纵队"），结果几乎注定，没有戏剧性。
另外，反事实分两种，主线只做其中一种：
• 决策反事实——在同一态势下换个决策（"粟裕换成打五军会怎样"）。它直接对应"验证决策"的卖点，数据需求少（只要同一初始态势加不同方案，不用重构战场环境），天然带叙事性。
• 状态反事实——改变某个客观变量（天气、兵力、时间，如"如果黄百韬晚到12小时"）。留作番外，主线别碰。
怎么判断一个选题属于哪种？一句话：这个变化是不是指挥官自己能选的？打谁、往哪走、先攻先守是他手里的选项，选哪个他能做主——换打法，能做主线；多两个炮纵队、下雨、援军早到是老天和上级发的牌，他自己变不出来——改条件，只能做番外。而且改条件的口子一开就收不住：多炮纵队就得配套多弹药、多民工，条件一环扣一环全跟着变，推出来的东西没法跟历史对答案。
三、第一遍怎么跑准：蓝方AI与参数标定
第一遍的全部意义是证明程序靠谱，这要过两道关。
第一关：程序里的国军得像国军
蓝方AI（程序里的国军反应规则）最难的问题是：历史上国军怎么应对，在程序里也会怎么应对吗？有三档做法，难度递增。
档位	做法	可信度	工作量
低	蓝方完全按史实行动，不响应红方方案	低	半天
中	蓝方用简单反应规则（如"被围则收缩待援 + 邻近兵团驰援"）	中	一周
高	蓝方用AI（MCTS/RHEA）自主决策	高	一个月+
建议从中档起步。怎么判断蓝方AI及格不及格？一条底线：挨打的部队必须会还手。第二遍里红方改打第五军，如果邱清泉还按历史剧本纹丝不动，那他不是对手，是木偶——赢一个木偶不叫本事，结论在开跑前就写好了，推演什么也没验证。反过来，远处没挨打的兵团基本按原计划走反而是合理的（他不知道出事了，这正是史实里国军增援迟缓的原因之一）。低档做法“完全按史实行动”可信度低，就低在挨打的人也不还手；中档那三条规则（交战减速、被围求救、援军照地形走）补的正是这一块。
具体规则可以这样写：
```python
# 蓝方简单反应AI规则集（示意）
if unit.is_engaged:  # 交战时
    unit.speed *= 0.3  # 机动下降
    if unit.besieged and unit.supply < 0.3:  # 被围且补给断
        unit.request_reinforcement(nearest_kmt_unit, radius=100)  # 呼叫100km内援军
if unit is reinforcement:
    # 邱清泉式反应：优先救援但受地形限制
    if terrain.is_huangfanqu:  # 黄泛区
        unit.speed *= 0.6
    unit.move_to(besieged_unit.position)
```
蓝方AI的行为必须用史实验证：拿"史实的红方方案"让蓝方AI跑一遍，看它的反应是否贴近历史上国军的实际动作。如果AI反应和史实不符，说明反应规则有问题，先校准再往下走。这个"用史实校准AI"的过程本身就是视频内容——观众看到为了严谨做了这么多步，人设立刻立住。
第二关：战斗力系数得用史实反推
交战解算用兰彻斯特方程的平方律（现代火器战争），攻守双方各有一个战斗系数，不能拍脑袋定，要用史实数据反推——比如"开封攻坚，3万守军48小时被歼"这条史实，就能反推出攻方系数该是多少。
```python
# 用史实数据反推战斗系数
# 史实：开封守军3万人（整68师等），华野3Z+8Z约8万人，48小时破城
# 设攻方系数 alpha，守方系数 beta（守军依托城防，beta有加成）
# 用兰彻斯特平方律，在 T=48h 时守军战损率应约 90%
# 试不同的 alpha/beta 组合，找到符合史实的解
from scipy.optimize import minimize
def loss_rate_diff(alpha, beta, A0=80000, B0=30000, T=48):
    # 平方律解析解
    import math
    r = math.sqrt(alpha*beta)
    c = math.sqrt(beta/alpha)
    B = B0*math.cosh(r*T) - (1/c)*A0*math.sinh(r*T)
    actual_loss_rate = 0.9
    predicted = max(B, 0)/B0
    return abs(predicted - (1-actual_loss_rate))
# 用优化器找最优参数
```
这个标定方法本身也可以做成一期番外（"我是怎么给引擎调参数的"），军事区观众对这种"幕后过程"内容接受度极高。
两道关背后是明确的分工：
• qtgame-war（主引擎）：机动模型（六角格地图、行军速度、地形修正）、交战触发（判断两个部队是否接触）、交战解算（调用 Jomini 的兰彻斯特方程）、蓝方AI（上面的反应规则）、时间轴推进（6小时/回合，推演30–40回合，豫东全程）。
• Jomini（数学底座）：平方律解算，参数由你用史实标定。
• 输出层：每回合导出JSON（`{turn, unit_id, position, strength, morale, engaged_with}`），交给 Blender/Godot 渲染。
四、第二遍的纪律：什么都不许变
第二遍最容易变味——推演结果不好看时，人会下意识想调参数。所以要先把"什么都不变"写成清单：
不变量清单（6月15日豫东）：
□ 双方部队位置（各纵队坐标）
□ 双方兵力、装备、战斗力系数
□ 邱清泉、胡琏、区寿年、黄百韬各兵团的位置与机动速度
□ 黄泛区地形、道路状况
□ 天气、昼长（影响空袭与机动）
□ 后勤补给状态
□ 双方指挥官的反应速度参数（这是最敏感的）
任何一条"不变量"被偷偷改变了（比如为了推演结果好看把邱清泉的行军速度调慢了），推演就从"验证"变成了"编故事"——这是军事区观众最反感的行为。
还有一条容易漏：信息不对称。粟裕6月15日决策时并不知道黄百韬会从东边杀过来，所以第二遍里的红方也不能有"上帝视角"——如果你的AI在换命令的分支里提前调兵防黄百韬，那就是作弊。
两遍的命令本身也要用同一张"决策描述表"来写，避免叙述性偏差：
```python
# 决策描述表：6月15日分叉点
historical_plan = {
    "name": "改打开封（史实）",
    "phase_1": {"action": "siege_kaifeng", "units": ["3Z", "8Z"], "target": "开封守军"},
    "phase_2": {"action": "block_aid", "units": ["1Z","4Z","6Z","11Z(中野)"], "line": "睢杞线"},
    "phase_3": {"action": "field_battle", "target": "区寿年兵团"}
}
counterfactual_plan = {
    "name": "坚持打五军（反事实）",
    "phase_1": {"action": "envelop", "units": ["1Z","4Z","6Z","8Z"], "target": "邱清泉第五军"},
    "phase_2": {"action": "block_aid", "units": ["3Z","10Z"], "line": "鲁西南北线"},
    "phase_3": {"action": "pursue", "condition": "五军被歼后转入追击"}
}
```
关键：换的命令必须"在决策者当时的信息条件下"是合理的——粟裕坚持打五军本来就是原方案，这个反事实才成立。如果做"粟裕用火星科技"那种反事实，就没有讨论价值。
五、不只跑两遍：一共跑三组
• 史实组：史实命令 + 蓝方史实行为 → 用于校准（结果应接近真实史实）
• 反事实组：换命令 + 蓝方AI反应 → 主推演
• 敏感性组：换命令 + 蓝方AI反应的参数扰动（比如蓝方反应速度±20%） → 看结果是否稳定
敏感性组是学术推演的标配，但对视频来说是隐藏加分项——可以在视频里只用一句话带过（"我们还测试了参数变化±20%的情况，结论不变"），但这句话的杀伤力巨大。
跑完输出"结果差异表"：
指标	史实组（校准）	反事实组	差异
开封是否攻克	是	否（未攻城）	-
歼敌数	9.3万（史实）	待推演	?
自损数	3.3万（史实）	待推演	?
邱清泉兵团状态	未受重创	待推演	?
中原战局影响	打破僵局	待推演	?
六、结果怎么讲：三层结构
推演结论绝对不能简单说"X比Y好"，要用三层结构呈现：
• 第一层：数据呈现——把三组推演的对比表格放出来，用"引擎推演显示"作为限定语，不下价值判断。
• 第二层：机理解释——解释为什么会这样（比如"反事实方案下红方被三面合围，是因为鲁西南狭小地带无法展开兵力优势，这正是平方律的数学体现"）。
• 第三层：历史印证——引回到粟裕自己的判断："粟裕在回忆录里说'不能稳操胜券'，和引擎推演的结论一致……"——用引擎印证历史人物，而不是用历史人物印证引擎，这个方向别搞反了。
七、最容易翻车的五个地方
翻车点1：拿结果倒推过程
跑出来的推演结果如果和历史不符，绝不可以说"这说明历史记载有误"——引擎是粗糙模型，历史是真实发生的事，冲突时先怀疑参数，别怀疑史实。这是学术反事实推演的铁律。
翻车点2：偷偷改参数让结果好看
如果邱清泉AI表现得太傻导致红方大胜，观众一眼就能看出来。敏感性测试的目的就是检验结果是不是依赖某个特定参数——如果结果对参数极其敏感，就老实说"这个推演在参数A下得到结果X，在参数B下得到结果Y，说明这个决策的关键是XXX"。
翻车点3：过度戏剧化反事实结果
"如果粟裕坚持打五军，华野会被全歼"这种结论过于绝对，会招致军事区高手的驳斥。正确的表达是"引擎显示反事实方案下红方可能承受更大损失"——保留模糊度，展示推演过程，不下死结论。
翻车点4：忽略信息不对称
见第四条纪律。症状是反事实分支里的红方提前知道了未来（如提前防黄百韬），推演变成作弊演示。
翻车点5：把推演当"答案"，其实它只是"参照"
学术界的反事实推演被批评最多的就是这一点。在视频里要主动说清楚："引擎推演不是对历史的审判，而是帮助我们理解当时决策者面临的约束"——这句话加上去，就从"民科沙盘UP主"直接升级为"严肃军事内容创作者"。
八、一期完整内容结构示范
以首期"6月15日改打开封"为例：
```
0:00-0:30   钩子：粟裕军令状+两次电报
0:30-2:00   分叉时刻：6月15日态势图，交代原方案vs新方案
2:00-4:00   方法论展示（1分钟）：
            - 不变量清单快闪
            - 蓝方AI的史实校准过程
            - （这段是差异化核心，一定要放）
4:00-8:00   史实组推演：跑历史方案，展示过程与结果
8:00-12:00  反事实组推演：换命令打五军
            - 重点展示蓝方AI如何反应（邱清泉/胡琏合围）
12:00-14:00 结果对比表+机理解释（平方律+地形约束）
14:00-15:00 历史印证：粟裕回忆录+中央"独立处置"电报

```
总长控制在15–20分钟，方法论展示部分压缩到1–2分钟，但一定要放——这是灵魂。
收尾：先校准，再反事实
先把"史实组校准"这一步做扎实，让引擎在史实条件下能跑出接近真实史实的结果，再开始换命令的分支——校准不过关就做反事实，等于在流沙上盖房子。反事实推演的核心不是"跑一遍引擎"，而是"守住不变量 + 校准蓝方AI + 用史实验证 + 保留模糊度"这套纪律：守住纪律，推演就是验证；守不住，就是编故事。
